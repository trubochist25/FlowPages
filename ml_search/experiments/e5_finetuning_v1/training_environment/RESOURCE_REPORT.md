## Технический запуск

16 уникальных запросов из обучающей выборки, два батча по восемь книг, 12 шагов AdamW с обновлением всех весов, learning rate 2e-5, weight decay 0.01, clipping 1.0, BF16 autocast. Метод — MultipleNegativesRankingLoss, scale 20, нормализованное косинусное сходство. Префиксы `query: ` и `passage: ` добавлены один раз.

Батчи проверены по обязательным условиям запросов и правилам `batch-policy.json`: без повторов книг, запрещённых пар совместимости и отложенных книг. Подробный состав сохранён в `smoke-batches.json`. Непроверенные добытые кандидаты не добавлялись. Это проверка технической работоспособности на двух батчах; совместимость всех будущих батчей предстоит проверить отдельно.

## Место и время полного эксперимента

Начальная проверенная конфигурация: этот ноутбук, батч 8, BF16, лимит 512, AdamW. Увеличение батча пока не проверено. Ноутбук подключить к питанию; доступная видеопамять меняется в зависимости от других приложений.

Линейная оценка только обновлений весов по измеренной скорости:

| Объём | 1 эпоха | 3 эпохи |
| --- | --- | --- |
| 512 примеров | около 9 с | около 26 с |
| 1000 примеров | около 17 с | около 50 с |

Эти числа не включают первоначальный запуск CUDA, более длинные профили, подбор совместимых батчей, загрузку, сохранение и оценку качества. Реалистичный рабочий резерв — **1–3 минуты на одно обучение 512 примеров до трёх эпох**, **2–5 минут для 1000**. Для двух скоростей обучения и проверки сохранений на dev разумно выделить **10–30 минут**; сама оценка dev ещё не измерена, особенно при использовании CPU. Это предварительная оценка, которую уточнит журнал полного эксперимента. Время редакционной проверки новых батчей сюда не входит.

Загрузка зависимостей при подготовке заняла несколько минут: один пакет PyTorch — 2,75 ГБ. Этот расход не повторяется при каждом запуске готовой среды.

Проверочное сохранение: `training_environment/smoke-model/`, состояние оптимизатора: `training_environment/optimizer-state.pt`. Это технические артефакты. Все последующие модели, журналы и индексы также хранить в папке эксперимента; действующую модель и индекс не заменять на этом этапе.

Метод и правила уникальности батчей сверены с [документацией Sentence Transformers](https://www.sbert.net/docs/package_reference/sentence_transformer/losses.html); установка CUDA-версии — с [официальной страницей PyTorch](https://pytorch.org/get-started/locally/). Все численные результаты выше получены на этом компьютере либо явно обозначены как оценки.

## Воспроизведение

Из корня проекта для нового окружения: создать Python venv, установить `requirements-training.txt`, затем сохранённый `requirements-lock.txt` для закрепления остальных версий. Для технического запуска использовать `ml_search/.venv-training/Scripts/python.exe -m ml_search.experiments.e5_finetuning_v1.smoke_training`. Сценарий откажется перезаписывать существующий `smoke-model`: для повторного запуска задать новую папку результатов в сценарии.

При первом запуске обнаружена и исправлена обработка дополнительных нетензорных полей входа Sentence Transformers. Сохранены первый и успешный журналы. Это исправление экспериментального сценария; рабочий код поиска не менялся.
