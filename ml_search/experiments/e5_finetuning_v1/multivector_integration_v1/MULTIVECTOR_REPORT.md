# Многовекторное ранжирование FlowPages

## Решение

Лучший проверенный вариант интеграции — дообученная E5, соответствующий ей
основной индекс, прежние веса поиска, обработчик названий и дополнительный
многовекторный индекс полей книги. Вариант подключён только экспериментальным
флагом и не заменяет рабочий поиск по умолчанию.

Для каждой книги заранее рассчитаны четыре вектора:

- сюжетная часть поискового профиля;
- краткая аннотация;
- структурированная часть профиля с характерными деталями;
- жанры, темы, настроение и темп.

Запрос кодируется один раз. Итоговая оценка объединяет текущий полный балл
с максимальным совпадением по четырём полям. Доля нового сигнала — 0,60.
Навигационные запросы с распознанным названием или автором остаются на прежнем
маршруте.

## Почему выбран поиск по всему каталогу

В текущем первом этапе подходящая книга присутствовала только в 43,59% топ-10,
51,28% топ-30 и 53,85% топ-50 настроечных запросов. Поэтому перестановка только
топ-20 или топ-50 не могла исправить почти половину ошибок.

Обычный полевой reranker топ-50 дал локальный прирост, но leave-one-family-out
проверка снизила Hit@3 на 5,13 процентного пункта. Обучаемый линейный reranker
на 34 проверенных триплетах также не перенёс выигрыш: NDCG на исключённых
семействах снизился на 0,0041. Оба варианта отклонены.

Полный многовекторный поиск сохранил выигрыш при исключении целых семейств:
NDCG@10 +0,0385 и Hit@10 +5,13 процентного пункта. Это стало основанием для
интеграционной проверки.

## Улучшения и ухудшения

Три запроса, где целевая книга отсутствовала в топ-10, получили её на второй
позиции. Ещё у нескольких запросов книга поднялась с 4-й на 1-ю, со 2-й на
1-ю и с 4-й на 3-ю позиции.

Есть неоднородность внутри семейств. Например, NEW-F07-V2 улучшился со 2-й до
1-й позиции, но NEW-F07-V1 опустился с 5-й за пределы топ-10. Также отмечены
падения 4→10, 3→8, 6→10, 3→6, 3→5 и 4→5. Это запрещает считать изменение
безусловным улучшением каждого запроса, несмотря на положительный общий итог.

## Совместимость и безопасность подключения

Рабочий поиск по умолчанию не изменён. Эксперимент включается переменной
`ML_SEARCH_MULTI_VECTOR_RERANKER=1`; скрипт `run_experimental.ps1` подключает
модель и оба согласованных индекса вместе.

Многовекторный индекс проверяет число книг, размерность, модель, хеш каталога и
собственную контрольную сумму. Несогласованная пара модель–индекс завершает
запуск ошибкой вместо скрытого смешивания векторов.

Прошли проверки названия, опечатки в названии, автора, строгих фильтров,
`no_matches`, некорректного запроса, семантической неопределённости и
рекомендаций. Полный набор содержит 98 успешно пройденных тестов.

## Ограничение закрытого теста

Файл из 99 новых запросов содержит ноль judgments и помечен как
`query_draft_frozen_not_a_ready_independent_test`. Поэтому закрытый NDCG по нему
вычислить невозможно. Конфигурация после просмотра структуры файла не менялась.
До производственного переключения эти запросы нужно независимо разметить,
после чего один раз применить зафиксированную конфигурацию без дополнительного
подбора по результатам.

## Итог

Многовекторный вариант — лучший из проверенных способов интеграции и готов к
экспериментальному запуску. Он пока не является основанием автоматически
заменить рабочий поиск: отсутствует размеченный закрытый тест, а в настроечной
выборке остаются отдельные заметные ухудшения.
