# Архитектура поискового ядра

## Поток запроса

```text
Запрос пользователя
  → исправление раскладки или транслитерации по алиасам каталога
  → распознавание названия и автора
  → извлечение мягких предпочтений из оставшейся части запроса
  → применение строгих фильтров интерфейса
  → E5 embedding запроса
  → сравнение с 1000 embeddings поисковых профилей книг
  → текстовое совпадение названия, автора и редких деталей профиля
  → гибридное ранжирование
  → объяснение результата
```

Поиск выполняется полным матричным сравнением `1000 × 384` для E5-small. Для
текущего каталога отдельная векторная база не требуется.

## Строгие и мягкие условия

`SearchFilters` содержит строгие ограничения:

- цена;
- автор;
- жанр;
- страницы;
- год;
- возрастной рейтинг;
- настроение;
- темп.

Книга, не прошедшая строгий фильтр, исключается до ранжирования.

Ограничения, распознанные в тексте, мягкие. Например, слово `короткий`
создаёт предпочтение до 250 страниц, но книга на 270 страниц может остаться
в выдаче с меньшим баллом.

## Ранжирование

Для смыслового запроса без явно распознанных характеристик:

```text
70% — embedding E5
25% — текстовые совпадения
3%  — популярность
2%  — совокупный сигнал рейтинга
```

Если распознаны жанр, настроение, темп, объём или год:

```text
70% — embedding E5
23% — текстовые совпадения
2%  — структурированные характеристики
3%  — популярность
2%  — совокупный сигнал рейтинга
```

Внутри структурированных характеристик жанр имеет больший вес, чем
настроение, а настроение — больший, чем темп или год.

Если найдено уверенное совпадение названия или автора, формула переключается:

```text
25% — embedding E5
60% — название или автор
10% — метаданные
3%  — популярность
2%  — совокупный сигнал рейтинга
```

Совокупный сигнал не является третьим пользовательским рейтингом и в
интерфейсе не показывается. Он объединяет два независимых источника:

- OpenLibrary — внешний рейтинг и холодный старт;
- FlowPages — среднее только по одобренным отзывам покупателей сайта.

При отсутствии отзывов FlowPages сигнал полностью равен нормализованному
рейтингу OpenLibrary. Затем доля FlowPages плавно растёт по формуле
`local_count / (local_count + 20)`: при 20 локальных отзывах источники имеют
равный вес. Меняется только пропорция источников внутри рейтингового сигнала;
его общий вес `2%` и вес популярности `3%` остаются неизменными. Для запроса
без текста также сохраняется исходная формула `70% популярность + 30% рейтинг`.

Однословное название получает этот вес только тогда, когда оно составляет
весь запрос или сопровождается автором. Для многословного названия требуется
совпадение непрерывной фразы как минимум из двух значимых слов. Обычные
подстроки и одно редкое слово сущностью не считаются.

Русский описательный запрос не переписывается словарём каталога. Для
латиницы строятся варианты по словам: неоднозначные `c`, `h`, `y`, `e`, `j`
сопоставляются с транслитерированными названиями, авторами и сериями. Полное
оригинальное название также участвует как алиас. Слова распознанной сущности
удаляются перед извлечением жанра и настроения, поэтому, например,
«философский камень» не превращается в запрос жанра «Философия».

## Поисковый профиль книги

Поле `searchText` — невидимый пользователю профиль, из которого строится
embedding книги. Он содержит название и автора, варианты жанров и тем,
настроение, темп, возраст, объём, год, целевую аудиторию и подтверждённые
исходными метаданными сюжетные детали. Профиль не заменяет пользовательскую
аннотацию и не содержит сгенерированных фактов о сюжете.

Все профили ограничены 512 токенами E5. Редкие слова из профиля (например,
`пирокинез` или `цензура`) дополнительно участвуют в лексическом сигнале,
чтобы конкретная деталь не потерялась внутри общего семантического смысла.

## Хранение

- `data/book_catalog/catalog.json` — исходные характеристики книг;
- `data/ml_search/indexes/multilingual-e5-small/` — индекс и manifest E5-small;
- `data/ml_search/local-model` — полностью локальная копия E5-small;
- `oc_book_metadata` — структурированные характеристики для OpenCart.

Единственное допустимое значение `ML_SEARCH_MODEL` и `--model` — `small`.
Индекс считается устаревшим, если изменился каталог, модель, размерность или
порядок `product_id`.

## API

- `POST /search` — поиск;
- `POST /recommend` — рекомендации по обезличенным пользовательским сигналам;
- `GET /suggest` — быстрые подсказки названий и авторов;
- `GET /analyze` — результат разбора запроса;
- `GET /facets` — допустимые значения строгих фильтров;
- `GET /health` — состояние сервиса.

OpenCart будет обращаться к API со стороны PHP. Браузеру пользователя не
потребуется прямой доступ к Python-порту.

В `POST /search` OpenCart передаёт разреженную карту `local_ratings` только
для товаров с одобренными отзывами. Ответ возвращает `external_rating`,
`external_rating_count`, `local_rating`, `local_rating_count` и служебный
`ranking_rating` раздельно. Доступны отдельные сортировки
`rating_external_desc` и `rating_local_desc`; старое значение `rating_desc`
сохранено как совместимый псевдоним внешнего рейтинга.

## Рекомендационный поток

```text
5 секунд видимого времени в карточке
  → OpenCart сохраняет просмотр в сессии гостя или в MySQL покупателя
  → главная собирает просмотры + избранное + корзину + покупки
  → PHP передаёт только product_id, тип, давность и силу сигнала
  → взвешенное среднее существующих E5-векторов образует профиль интересов
  → стратегии balanced и explore независимо ранжируют общий каталог
  → MMR-подобный отбор снижает повторы содержания, авторов и серий
  → OpenCart загружает актуальные товары, цены и остатки из MySQL
```

Стратегия `balanced` сохраняет основной акцент на сходстве с профилем.
Стратегия `explore` снижает этот акцент, добавляет 14% жанровой новизны,
5% детерминированной случайности и повышает силу диверсификации с 18% до 32%.
Так вторая полка остаётся персональной, но чаще проверяет соседние и редкие
жанры. Веса действий возрастают в порядке
`просмотр < избранное < корзина < покупка`.

Карточка товара использует третью стратегию `similar`. Она получает только
`anchor_product_id`, поэтому история посетителя не меняет смысл блока. Текущая
книга исключается, 76% оценки задаёт близость к её E5-вектору, а небольшой
MMR-вес 14% не даёт ряду схлопнуться в одного автора, одну серию или несколько
почти одинаковых книг. Если ML-сервис недоступен, OpenCart использует штатные
связанные товары как аварийный fallback.
Давность ослабляет сигнал с разным периодом полураспада: 30 дней для
просмотров, 90 для избранного, 14 для корзины и 180 для покупок. Релевантность
к профилю остаётся главным фактором, а метаданные, популярность и рейтинг
используются как малые стабилизирующие сигналы.

В MySQL хранится только агрегированная история успешных просмотров
авторизованных пользователей в `oc_customer_product_view`; гостевая история
хранится в стандартной сессии OpenCart. Python не получает ни `customer_id`,
ни идентификатор сессии и не хранит пользовательские данные. При пустой
истории `balanced` включает cold-start ранжирование: `62% популярность + 33%
рейтинг + 5% детерминированная для сессии случайность`. Для `explore` cold
start использует `47% популярность + 28% рейтинг + 17% редкость жанра + 8%
случайность` и более сильную диверсификацию. Полки главной идут в порядке:
«Рекомендуем вам», «Попробуйте другое», «Популярное сейчас». Отдельных рядов
новых поступлений и высоко оценённых книг нет.
