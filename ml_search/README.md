# Локальное ML-ядро поиска FlowPages

Сервис по умолчанию использует дообученную версию `multilingual-e5-small`
с отдельным индексом и многополевым переранжированием. Он объединяет четыре независимых
сигнала:

- семантическое сходство E5;
- усиленное совпадение названия и автора;
- мягкие предпочтения из свободного запроса;
- строгие фильтры интерфейса.

Модель и индекс работают локально. Внешние API во время поиска не вызываются.
Подробная схема и веса описаны в `ARCHITECTURE.md`.

## Установка

Из корня OpenCart:

```powershell
& powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\ml_search\download_model.ps1" -Model small
& ".\ml_search\.venv\Scripts\python.exe" -m pip install -r ".\ml_search\requirements.txt"
& ".\ml_search\.venv\Scripts\python.exe" -m ml_search build-index --model small
```

Локальная копия модели хранится в `data/ml_search/local-model`. После загрузки
сервис может работать без сети; `run.ps1` принудительно включает офлайн-режим
Hugging Face. `small` — единственная предусмотренная модель. Для совместимости
её можно указать явно:

```powershell
$env:ML_SEARCH_MODEL = "small"
```

Параметр `--model small` также принимается CLI и имеет приоритет над переменной
окружения. Любое другое значение завершается ошибкой конфигурации.

## Запуск

```powershell
& powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\ml_search\run.ps1" -Model small
```

По умолчанию API доступно на `http://127.0.0.1:8765`.
`run.ps1` запускает выбранную по итогам закрытого теста конфигурацию. Для
аварийного отката нужно остановить текущую службу и выполнить:

```powershell
& ".\ml_search\run.ps1" -Profile legacy
```

Возврат к выбранной конфигурации выполняется обычным `ml_search\run.ps1`.

Основные маршруты:

- `POST /search` — поиск и строгие фильтры;
- `POST /recommend` — персональная content-based выдача по истории действий;
- `GET /suggest?q=гарри` — подсказки;
- `GET /analyze?q=короткий страшный детектив` — разбор запроса;
- `GET /facets` — значения фильтров;
- `GET /health` — состояние модели и индекса;
- `GET /docs` — интерактивная документация.

## Интеграция с OpenCart

Маршрут `product/search` обращается к API только по локальному адресу
`127.0.0.1:8765`. Python возвращает ранжированные `product_id`, после чего
OpenCart загружает актуальные товары, цены и остатки из своей базы.

Интерфейс передаёт строгие ограничения по цене, автору, жанру, страницам,
году, возрасту, настроению и темпу. Доступны сортировки `relevance`,
`price_asc`, `price_desc`, `rating_external_desc` и `rating_local_desc`.
Старое значение `rating_desc` остаётся совместимым псевдонимом рейтинга
OpenLibrary. Сначала ядро формирует релевантный пул, затем применяет выбранную
коммерческую сортировку.

OpenLibrary и отзывы FlowPages передаются и отображаются раздельно. В
релевантности они объединяются только во внутренний сигнал качества: при 20
одобренных отзывах источники получают равный вес, затем влияние FlowPages
плавно растёт. Общий вес рейтингового сигнала и популярности не изменён.

Если сервис не отвечает, OpenCart автоматически использует стандартный
поиск по каталогу и показывает пользователю уведомление. Расширенные фильтры
в аварийном режиме не применяются.

## Персональные рекомендации

Главная страница дважды обращается к `POST /recommend` с обезличенными сигналами текущего
посетителя: подтверждённые просмотры, избранное, корзину и, для
авторизованного покупателя, покупки. Идентификатор покупателя и идентификатор
сессии не покидают OpenCart. Python объединяет
эмбеддинги книг в профиль интересов, учитывает давность и силу действий и
диверсифицирует итог по авторам, сериям и содержанию.

Просмотр засчитывается только после 5 секунд видимого времени в карточке.
При построении профиля OpenCart учитывает до 30 последних уникальных
просмотренных книг за 90 дней. Для гостя история живёт в его сессии, для
авторизованного пользователя — в MySQL.
Таблица истории создаётся один раз командой:

```powershell
php ".\tools\book_catalog\install_recommendation_history.php"
```

Книги из корзины, избранного и покупок служат сильными исходными сигналами,
но сами не рекомендуются. Уже просмотренная книга может появиться повторно,
однако не в первых четырёх позициях и не чаще одной на десять результатов.
Первая полка использует стратегию `balanced`: если сигналов нет, она строится
в режиме холодного старта — 62%
популярности, 33% рейтинга и 5% небольшой случайной примеси. Случайное зерно
фиксируется в сессии, поэтому состав не скачет при обновлении страницы. Ряд
«Новые поступления» удалён полностью. Вторая полка «Попробуйте другое» использует
стратегию `explore`: связь с профилем интересов сохраняется, но повышены веса
новых и редких жанров, случайной примеси и MMR-разнообразия. В холодном старте
её формула: 47% популярности, 28% рейтинга, 17% редкости жанра и 8% случайности.
Третья полка — «Популярное сейчас»; отдельной полки «Высоко оценены» больше нет.

В карточке товара `strategy=similar` строит отдельный ряд «Похожие книги».
Текущий товар передаётся как `anchor_product_id`, остаётся главным смысловым
ориентиром и никогда не возвращается в собственном блоке. Формула ряда: 76%
семантической близости, 12% совпадения метаданных, 5% популярности, 4% рейтинга
и 3% детерминированной случайности. Небольшая MMR-диверсификация в 14%
предотвращает однообразные повторы авторов, серий и почти одинаковых книг.

## Пример поиска

```json
{
  "query": "короткий страшный детектив без мистики",
  "filters": {
    "price_max": 900,
    "pages_max": 300,
    "age_ratings": ["16+", "18+"]
  },
  "sort": "relevance",
  "limit": 20
}
```

Ограничения, найденные в тексте, остаются мягкими. Поля объекта `filters`
являются строгими: книга, не прошедшая хотя бы одно условие, в выдачу не
попадает.

## Обновление поисковых профилей

Старый генератор `tools/book_catalog/enrich_search_text.mjs` создаёт шаблонный
`searchText` без проверки содержательных утверждений и больше не должен
использоваться для обновления каталога. Новый версионированный конвейер описан в
`tools/book_catalog/SEARCH_TEXT_V2.md`. Он собирает source pack, требует цитату
для каждого факта, независимо проверяет профиль и сначала создаёт параллельный
`catalog-v2-draft.json`.

После принятия нового каталога индекс нужно перестроить:

```powershell
& ".\ml_search\.venv\Scripts\python.exe" -m ml_search build-index --model small
```

Для синхронизации профилей с `oc_book_metadata` без переимпорта товаров:

```powershell
php ".\tools\book_catalog\refresh_search_text.php"
```

Индекс сам не обновляется при редактировании `catalog.json`: перестроение
является явной операцией, а SHA-256 каталога в manifest защищает от запуска
устаревшего индекса.

## Командная диагностика

```powershell
& ".\ml_search\.venv\Scripts\python.exe" -m ml_search analyze "ufhhb gjnnh"
& ".\ml_search\.venv\Scripts\python.exe" -m ml_search search "dostoevskiy" --model small --debug
& ".\ml_search\.venv\Scripts\python.exe" -m unittest discover -s ml_search/tests -v
& ".\ml_search\.venv\Scripts\python.exe" -m ml_search.evaluate_models
& ".\ml_search\.venv\Scripts\python.exe" -m ml_search.evaluate_alchemy --output ".\data\ml_search\step9-alchemy-evaluation.json"
& ".\ml_search\.venv\Scripts\python.exe" -m ml_search.evaluate_relevance --output ".\data\ml_search\relevance-calibration-report.json"
```

`evaluate_models` прогоняет 77 фиксированных регрессионных запросов для
`small`. `evaluate_alchemy` выполняет приёмку минимум на 100 рецептах, а также
проверяет строгие исключения, фильтры, противоречия, пустые состояния,
происхождение результатов из каталога и время ранжирования. Отчёты выводятся в
консоль; файл создаётся только при явном `--output`.

`evaluate_relevance` сопоставляет положительную и негативную выборки, отдельно
подбирает пороги для навигационного и семантического поиска, а также для
якорного, свободного, гибридного и полностью структурированного режимов
«Алхимии». Покрытие ожидаемых книг считается отдельно от качества порога:
отсутствующий результат не подменяется нулевой оценкой релевантности.

Реальный PHP-клиент можно отдельно проверить при заведомо недоступном ML-адресе:

```powershell
& "<path-to-php>\php.exe" ".\tools\book_catalog\test_ml_search_unavailable.php"
```

Тестовый backend `--backend hashing` существует только для разработки без
скачанной модели и не должен использоваться на сайте.

## Хранение моделей и индексов

Индекс размерностью 384 хранится в
`data/ml_search/indexes/multilingual-e5-small/`. В каталоге находятся
`book-index.npz` и `manifest.json`.
Сервис проверяет имя модели, размерность и SHA-256 каталога перед запуском.
